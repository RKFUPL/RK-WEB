# Sale announcement and compact allocation UI

Campaign Details now saves `showAnnouncementRunner`, `announcementStartsAt` and `announcementFeatured`. Existing campaigns default to runner disabled; no database migration or activation occurs. The announcement time is parsed in the saved campaign timezone (default Asia/Kolkata) and must be at or before launch when enabled. Message previews are calculated by a read-only authenticated backend endpoint.

`GET /api/sales/announcement` returns one safe announcement, server time, live availability and the next relevant boundary. Featured enabled campaigns have priority, with live featured before upcoming featured. Upcoming featured campaigns use nearest launch and then campaign ID. If no eligible featured campaign exists, enabled nonfeatured campaigns follow the same live/upcoming ordering. Paused, draft, archived, expired and globally disabled campaigns are unavailable.

Upcoming campaigns require a saved verified banner, an opened announcement window, a valid schedule and explicit publication. Calendar days-to-go use the campaign timezone, including local midnight. `/sale/preview/[slug]` fetches `/api/sales/teaser/<slug>` server-side with no cache. This endpoint supplies banner/title/subtitle/schedule only, never items, product identities, discounts or prices. The public banner route independently enforces live eligibility or the same pre-launch gates. Teaser routes redirect to `/sale` only when the campaign is live and has eligible sale products; disabled or ended routes return normal not-found responses.

An eligible runner occupies a 32-pixel neutral strip at the top of StickyHeader, with readable 11px mobile and 12.5px desktop text. Loading, unavailable and inactive states render no runner or reserved space. A short height transition (disabled for reduced motion) smoothly inserts/removes the strip. The existing ResizeObserver follows the animated header height and includes this strip in `--rk-header-height`; portals and utility overlays retain their existing viewport stacking. The strip is a single accessible link; repeated moving text is hidden from assistive technology. Hover and keyboard focus pause it; reduced motion shows static text. SALE is the last desktop/mobile main navigation item after CONTACT, and is never shown solely because a pre-launch announcement exists.

Public state refreshes every 15 seconds and at server-reported launch, end, announcement-start and local-midnight boundaries. Boundary changes refresh navigation and existing canonical product/variant price quotes and cart prices. No browser timezone or client-supplied discount becomes authoritative. Network failures do not grant sale availability; checkout still independently prices database values. No cron is required. Administrative pauses and global toggle changes are observed on the next poll (or focus refresh).

The inventory editor is now a matrix with one row per saved colour/SKU and the union of actual configured sizes as columns. Unconfigured intersections display a dash and never generate an API bucket. Row, size-column and grand totals are derived from the same editable quantities. A sticky row label and local horizontal scroll keep narrow drawers usable. Allocation reason, exact payload, stock preservation, audit and stale-edit protections remain unchanged.

Validation uses synthetic storage and mocked/blocked external transports. The isolated browser fixture includes short real-time campaign schedules to exercise teaser-to-live and expiry transitions. No existing local/test/production campaign, inventory, customer, payment or messaging records are modified by this implementation or these fixtures.

The saved teaser banner spans the full available page width without 100vw overflow. COMING SOON is a centred, single-line, 50-percent-opacity ivory editorial watermark directly over the clear image, with responsive clamp sizing and no background strip. The banner uses its natural aspect ratio to preserve every subject; only the campaign text below it is width-constrained. Its top offset follows --rk-header-height.
